# Security and operational preparation

Identity handles password hashing/verification; no plaintext password, root account, token or connection string is committed. Seed roles/Admin only via the explicit bootstrap operator command. Public registration does not exist. Runtime secrets use environment variables or User Secrets. Repository-local author identity is independent of GitHub authentication.

Cookie authentication is HttpOnly/SameSite=Lax, 8-hour sliding expiration; production uses Secure=Always with HTTPS redirect and HSTS. Development/Testing permit local HTTP only. Security stamps are validated every request; user role/status changes revoke stamps. Services reload the active account and permissions for mutations within the serialized ledger transaction. UI hiding is supplementary. SalesStaff invoices/payment actions are owner-scoped; costs and supplier data are restricted. Last active Admin protection shares the same SQL lock as all business/admin mutations.

Every unsafe MVC and cookie-authenticated API method has global AutoValidateAntiforgeryToken, including login/logout. Fetch obtains a same-origin CSRF token and sends X-CSRF-TOKEN. Refresh token after identity changes. API cookie failures are proper ProblemDetails 401/403, not HTML redirects. No permissive CORS policy is configured. CSP disallows external scripts/styles, inline scripts, framing and foreign form targets. Razor output encodes data; cart builds user text with textContent. SQL uses EF parameters.

Identity persists five failed attempts followed by a 15-minute account lockout. A socket-IP fixed-window policy permits 15 login submissions per five minutes per app process. Failures do not reveal whether an account exists; timing equality is not guaranteed by the framework. X-Forwarded-For is not trusted. The IP limiter is local per process; before scaling out, deploy an explicitly trusted proxy and shared limiter design. Identity's internal password/lockout writes occur outside the business ledger gate; they do not change roles or stock. Infrastructure/transient errors should be investigated, never retried as partial stock statements.

Financial mutations require stable idempotency UUIDs and fingerprint their full payload. Atomic SQL transactions/app locks, rowversion, unique constraints and stock checks protect duplicate/concurrent mutations. Refunds cannot exceed collected funds; stock restoration is separate and one-time. See INVENTORY_CONCURRENCY.md. Application table access should be least privilege; direct external writers bypassing this design are unsupported.

The centralized handler sends safe error messages; stack traces and SQL errors stay out of user responses. EF sensitive-data logging is not enabled. Audit summaries exclude credentials and tokens. Logs and audit access need appropriate retention and restricted filesystem/database access. Responses are no-store except static asset paths. Health only exposes liveness, not database credentials or readiness internals. OpenAPI is Development-only. Configure AllowedHosts explicitly for deployment; the repository default permits loopback hosts only.

Image/file uploads are intentionally absent, so there is no exposed upload path. Real gateways/email integrations are absent. Supply-chain controls include package lockfiles, auditing of all transitive dependencies during restore with warnings treated as errors, vendored Bootstrap license and full-history Gitleaks scanning. No advisory is suppressed. Pkcs 10.0.13 is directly pinned to avoid vulnerable versions introduced by SQL client transitive dependencies.

Before deployment: obtain an authorized SQL instance/database, review migrations and back up data, separate migration/runtime principals, provision TLS and persistent protected Data Protection keys (shared across app replicas), secure environment secrets, define backups/restore and retention, confirm currency/tax/costing rules with business operators, configure host/proxy boundaries and monitoring, and run load/accessibility/upgrade validation. Do not expose Development or use TrustServerCertificate=true with an untrusted production SQL server. No paid deployment/infrastructure or Windows service installation was performed by this work.
